# Sleep-Harness Strategy Memory

> 本文件是给 Agent 阅读的“实验经验摘要”和“下一步计划”，不是实验结果的权威来源。
> 数值指标、运行状态、代码版本和 accept/rollback 决策必须以 `logs/run_history.jsonl` 中由 Harness 写入的记录为准。
> Agent 不得编造、推测或自行修改已经发生的实验指标。

## 1. 项目目标

在固定 Sleep-EDF 数据划分和固定评估器约束下，改进 PyTorch TinySleepNet 的睡眠分期表现。主要优化指标：Balanced Accuracy；辅助指标：Macro F1 和各类别表现。

## 2. 不可违反的约束

- 不修改固定评估器、数据划分文件、测试集或 Harness 安全机制。
- 训练阶段只能访问训练集；模型选择阶段只能使用验证集。
- 测试集只按预先规定的最终评估流程使用。
- 每轮优先提出一个可检验的主要假设，避免同时改动多个无关因素。
- 所有结论必须能追溯到 `run_history.jsonl` 的具体 run_id。
- 不得把随机模拟数据上的 smoke test 指标当作真实 Sleep-EDF 结果。

## 7. 下一步行动

1. 待真实数据训练与评估闭环跑通后，根据最近实验和最佳 run 选择一个新假设。
2. 优先避免重复执行“已尝试但没有改善”的相同配置。
3. 若证据不足，优先设计小规模、可归因的验证实验，而不是同时大改多个模块。

## 8. Agent 更新规则

- 实验开始前：读取本文件和最近若干条 `run_history.jsonl`，提出一个假设及修改计划。
- 实验结束后：Harness 先写入实际指标、运行状态、commit 和决策；之后才允许更新本文件中的经验摘要和下一步计划。
- Agent 只能更新第 4–7 节的解释性摘要和计划，不得伪造第 3 节中的指标，也不得改写历史事实。
- 每条经验必须引用一个或多个 `run_id`。
- 新证据与旧结论冲突时，保留历史记录，并注明结论被修正的原因；不要删除旧经验。
